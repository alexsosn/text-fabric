# Research: native levUp posting-set intersection costs (Text-Fabric v13.1.0)

Cross-project source: alexsosn/ORAEC-TF#82 and research-only PR #83, merged `710cda412974b6f795dbbcc902185656ae822496`. Full pinned actual ORAEC corpus 13,026 texts, 815,026 real tokens + three anchors, 998,775 TF nodes, 2,930 native CR nodes and 65 unchanged semantic TF feature SHA256 digests. A real matched-input native Text-Fabric recomputation of `tf.core.prepare.levUp` took **189.327805s wall** / **189.306695s CPU**; candidate source-equivalent inverted-posting membership took **175.134145s wall** / **175.114647s CPU**. Both had recorded process peak RSS high-water **6,500,268 KiB**. This was ONE native-first comparison, not a statistically established production speedup. The earlier prototype with cached oslots frozensets was rejected after raising peak RSS to 9,729,396 KiB; all slot membership copies are therefore forbidden in this alternative.

Source in THIS fork at `tf/core/prepare.py::levUp` matches Text-Fabric upstream 13.1.0. It builds `oslotsInv[s]` posting sets of non-slot containing nodes and repeatedly computes Python-level `functools.reduce(lambda x,y:x & oslotsInv[y], mList[1:], oslotsInv[mList[0]])`. Each `set.__and__` creates a temporary set. For long non-slot nodes this repeatedly allocates and intersects postings. Some TF nodes (lexical, controlled-value, hierarchy, references) contain noncontiguous slot sets; interval-based approximations are invalid.

Proposed implementation: obtain the same inverted postings for each node (eagerly, retaining native KeyError on missing posts); choose the shortest posting; filter its candidate nodes for membership in **all** required postings. For all slots S and postings P(s), intersection(P(s) for s in S) is exactly {m in P(s_min) : forall s in S, m in P(s)}. Keep slot-node behavior, empty node behavior, exact original descending rank sorting and interned output tuple structure. Preserve original `info/error` progress diagnostics and Text-Fabric `.tfx` cache behavior (no new pickle trust). This change lives in the native TF core; ORAEC's independent original-native source comparator should not be monkeypatched.
